# Vector math and geometry

Built-in vmath and geometry modules.

## Built-in vmath and geometry

All Hosts (Desktop, device and Wasm/browser) provide `require('vmath')` and `require('geometry')` by default, without App registration of native modules. `vmath` does not replace standard `math`; neither module depends on a Display device. See production header `libs/lua/include/h2_lua_numeric.h` and [Lua numeric API](https://github.com/GizClaw/gizos/blob/81e8cbfc64760b5bcc89e8be771393662e876ea5/guides/references/lua-numeric.md) for full argument and boundary contracts.

`vmath.buffer(count[,kind])` creates fixed-capacity userdata holding at most 65536 numbers. kind is `"f64"` (default, also used for nil) or `"f32"`, storing binary64 or binary32 respectively. Storage and equal-length transaction scratch are both charged through the VM allocator: `16 * count` or `8 * count` bytes respectively, plus fixed metadata/userdata overhead. Indices start at 1. Points are consecutive `x,y` or `x,y,z`, without nested tables. Allocate buffers, mesh writers and meshes during initialization and reuse them within frames. Successful batch calls allocate nothing; error messages may allocate. All numbers and results must be finite with absolute value at most 1e6. Out-of-range values, wrong types, invalid topology or insufficient capacity raise a Lua error, leaving published buffers and meshes unchanged.

Except for the explicitly specified prepared displacement/coefficient entry points below, every buffer in one call must use the same kind, including coefficients, weights, cameras, masks, indices, tags and mesh topology. Mixing kinds raises `mixed numeric buffer kinds (f32/f64)` before publication, even for empty prefixes; there is no implicit conversion. All-f32 calls use float arithmetic and single-precision math functions. Lua scalars are first checked for finiteness and the ±1e6 range, then converted to float at call entry; load converts each imported element once. Parameter intervals are checked at the selected precision; storage and arithmetic round at that precision, and very small values may underflow to zero. get/dot return ordinary Lua numbers. Pure scalar clamp/lerp/smoothstep/spring and standard math retain double semantics.

The math module provides scalar interpolation/clamping/spring stepping; buffer linear combinations, elementwise multiplication/division, polynomials, dot products, 3D length/normalization and channel gather/scatter; and batched Verlet, XPBD distance constraints and displacement damping. Physics inputs explicitly supply acceleration, inverse mass, constraint edges and compliance. Zero inverse mass fixes a node; time steps range over `[1e-6,.1]` seconds. `relax` clears lambda each call, offers bidirectional distance or tension-only constraints, and supports at most 256 points, 512 edges and 32 alternating iterations. It includes no collisions, materials or game rules.

`relax_sweep` performs one forward or reverse constraint sweep using two weights per edge and preserves lambda, allowing callers to combine extra constraints between sweeps. `damp_edges` updates previous-frame positions in edge order to damp axial displacement along the separation direction. `map` provides abs/sqrt/sin/cos/floor, `select_le` performs componentwise conditional selection, and `take` rearranges fixed-width data using one-based row indices. Arguments, capacity, aliasing and failure atomicity follow the production public header.

The geometry module provides 2D/3D affine transforms, weighted displacement and rotation, displacement prefix sums, polyline expansion, axis-plane splitting, and projection with near-plane clipping. A camera is `{fx,fy,cx,cy,near}`, looking along +Z in camera space, with projection `(cx+fx*x/z, cy+fy*y/z)` and `near >= .001`. Negative `fy` can flip screen Y. Splitting outputs `{side,source_index}`; projection outputs source segment indices, allowing Lua to choose colors. Lua still composes game formulas, camera parameters, materials, colors and time-step policies.

`geometry.mesh(vc,pc)` returns a writer and the existing public Display mesh. `geometry.update_mesh(writer,xy,topology,nv,np)` copies results directly into the mesh and returns that same mesh. Each topology row is `{kind,first,count,rgb565}`: kind 0 is a 3..128-point polygon and kind 1 a two-point line segment. xy and topology may both use f32; the writer and public Display mesh are independent of numeric precision. This operation neither draws nor presents; use existing Display batch drawing interfaces. f64 preserves smaller displacements; f32 halves data and scratch space and uses single-precision arithmetic. Batch calls eliminate per-point Lua/C boundary overhead. S3 frame rates and bit-for-bit equality across platforms are not yet promised; measure on devices with actual point and iteration counts.
