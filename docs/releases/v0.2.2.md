# GizMoth v0.2.2

## Fixes

- Fix sustained CPU usage near 100% in the macOS resident serial service after H2Loader initialization. Serial startup no longer starts the CLI platform's unused default-route monitor, which repeatedly woke on its own route-query responses.
- Preserve serial communication, H2Loader initialization and the existing initialization flow on Windows and Linux.

## Validation

- Add a macOS startup regression that verifies serial initialization creates no background thread and keeps the stateless memory/time services usable. Include it in CI alongside the existing synthetic serial and protocol tests.
- All three native test targets passed, covering startup, 10 synthetic PTY/file cases and 13 fake PAL/clock/device scenarios. No physical device installation or reboot was performed.
- In an isolated two-second idle probe, the original native initialization consumed 95.54% CPU; the fixed initialization rounded to 0.00%. This measures the native startup path, not total desktop usage under device traffic.

## Updating

Restart GizMoth and its resident serial service to load the fix. An older daemon can continue running after the desktop window closes. Finish or cancel device jobs and release external sessions before restarting the service; active serial connections briefly disconnect during the update.
