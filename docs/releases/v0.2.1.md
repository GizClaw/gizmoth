# GizMoth v0.2.1

## Device task sessions

- Identify each device WebSocket connection with its client name and required task title. Show the active client and task in the device list, detail view and waiting queue, including while the device is offline.
- Preserve the WebSocket and exclusive grant across serial disconnects, USB re-enumeration, H2Loader reboot and temporary port disable. Availability changes arrive as `device` events; the agent decides whether to keep waiting or close its connection.
- Continue on the same granted socket when `ready` becomes true. Offline physical commands return `503` without buffering or replay, while cancellation of the holder's existing job remains available.
- Keep probing previously recognized H2Loader devices through boot delays instead of silently falling back to plain serial.
- Disconnect a selected holder or waiter from GizMoth by its exact connection ID. Stale confirmations cannot terminate a replacement holder, and other waiting clients retain their queue positions.
- Improve task and connection-control layouts in narrow windows.

## Agent compatibility

Device command sessions now advertise `gizmoth.device.v2`. Update the GizMoth Skill from the Agents tab and provide `client` plus a short `title` when discovering or opening a device connection; `reason` is optional context. Older service protocols are rejected explicitly.

MCP and external HTTP remain query-only. Connect the returned WebSocket to request access, keep it open while pending, wait for `granted`, and run `send`, `install`, `reboot`, `refresh` and `cancel` on that same socket. Closing the socket releases it. Explicit administrator actions, revoked authorization and service shutdown can still end sessions.

## Validation and limitations

The change includes HTTP/WebSocket regressions with synthetic device workers for fast loss/recovery, worker replacement, offline cancellation, availability-event resynchronization, task metadata and targeted administrative disconnects. Physical-device firmware installation and reboot interoperability still require device and USB-driver verification.
