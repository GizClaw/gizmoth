# GizMoth v0.2.0

## Development environments

- Add **Dev Env** with chip cards, development-tool collections and a toolchain table backed by the independent [GizClaw/gizmoth-devenv](https://github.com/GizClaw/gizmoth-devenv) registry.
- Install managed Python 3.11.18/3.12.16 and Bazel through Bazelisk. Multiple versions can coexist, with exact matching dependencies shared between installations.
- Add a GizOS base host-tools collection containing Bazelisk and Python.
- Show full installation paths and usage, open installation folders, preview removals, and safely reinstall the same managed version. Register local toolchain folders without modifying or deleting their contents.
- Verify downloads by size and SHA-256, safely extract supported archives, and recover interrupted removal/replacement transactions. Failed refreshes preserve the previous catalog; concurrent refreshes and stalled requests are handled safely.
- Browse the real registry in an ordinary browser; installation and local management are available in the desktop app.

## Serial service and interface

- Add local serial ports in batches.
- Route external device commands through an exclusive service WebSocket. The same connection requests access, waits for a grant, carries commands and job events, and releases access on disconnect.
- Consolidate desktop-only notices, reduce duplicate device errors, and refresh Magpie styles with an offline fallback.

## Downloads and updates

Choose the installer for your platform: macOS Apple Silicon, macOS Intel, or Windows x64. The release also includes signed updater payloads and an update manifest for the desktop updater. macOS installers are signed and notarized.

## Current limitations

Chip SDK installation recipes remain planned. The GizOS collection installs host tools; framework source cloning and a complete firmware SDK/compiler setup are not included in this release. Git sources and arbitrary installer commands are not executed. Installing tools does not modify the system PATH or automatically activate a project environment.

Firmware project builds, Bluetooth serial ports and Remote GizMoth ports are not implemented. Serial firmware installation targets devices already running H2Loader and does not provide blank-board ROM recovery. Windows device interoperability still needs platform verification.
