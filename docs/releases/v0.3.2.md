# GizMoth v0.3.2

## Serial port cascading

- Connect another GizMoth using its LAN or Tailscale address and API key. HTTP, WebSocket and gRPC h2c share the service port; no HTTPS certificates are required.
- Display each remote computer as a distinct node with its own fan-out to serial ports. Group the port list by computer and retain the last known state when a remote node disconnects.
- Use the owning computer's exclusive-session queue for remote sends, firmware installation and reboot. Carry task titles and exact connection IDs through the gRPC protocol, retain grants across physical device loss, and prevent stale disconnect requests from ending replacement sessions.
- Upload firmware in checked chunks, look up jobs after ambiguous responses, and clean up cancelled uploads after background file operations close their handles.

## Fixes and validation

- Fix lock ordering between remote snapshots and new sessions, keep active uploads alive beyond the idle connection budget, and preserve an explicitly entered HTTP port 80.
- Block automatic service retirement during forwarded preparation, firmware uploads and live remote sessions, so updates cannot cancel an imported device's active job.
- Stabilize native simulator test setup around initial page navigation and WebGL readiness without changing race or metadata-only capture assertions.
- Include regression coverage for concurrent session opening, slow and cancelled uploads, certificate-free LAN connections, device-loss lease retention and exact-session disconnects.
- Preserve the macOS resident serial CPU fix from v0.3.1.

## Limitations

Cascading supports one remote level. A GizMoth exports only its own ports. Ordinary LAN traffic is plaintext; Tailscale supplies network encryption when used. Real two-computer physical-device operations and Windows Tailscale discovery still require platform verification.
